# Design Note

Every stage of this pipeline was chosen by running the alternatives against this corpus and test set, not by default or intuition — full comparisons are in `reports/`.

**Chunking, embedding, retrieval.** Semantic-section chunking (1024 tokens, no overlap) beat fixed-size and recursive-structural splitting. BGE-M3 beat multilingual-e5-large and a BM25 baseline, decided almost entirely by a cross-lingual recall gap (66.7% vs 5.6% recall@5) — this corpus is deliberately multilingual, and same-language quality wasn't the deciding factor. Dense retrieval alone (top_k=10) beat both a BM25/dense hybrid and every reranker tried; the reranker's 512-token cross-encoder window was truncating the same large, semantically coherent chunks that made chunking work well in the first place. The pattern across every stage: simpler won, and only because each alternative was actually measured.

**Generation.** No chain-of-thought — a single structured-output call returns `answer`, `citations`, and `sufficient_context` together, keeping latency down and making faithfulness a structural property (every claim must cite a retrieved `chunk_id`) rather than something hoped for. A low similarity threshold (0.55) is a cheap pre-filter for obviously off-topic queries only; answerable/unanswerable score distributions overlap too much on this corpus for a single threshold to safely do more, so the real answerable/unanswerable judgment happens inside the LLM call, which sees the actual retrieved text.

**Local vs. cloud.** OpenAI credits ran out mid-project, forcing a pivot to local models (Ollama). Both configs now live behind one `LLM_PROVIDER` switch rather than one replacing the other, since this was a cost-driven stopgap, not a permanent decision. The trade-off is explicit and measured, not hidden: local inference is $0 but runs 48–120s/call against a 10s budget, and a same-judge comparison against the original cloud answers shows the smaller local model is measurably less faithful (72% vs 92%) — traced to it frequently mis-copying citation IDs, not the retrieval or prompt design.

**Security.** PII is redacted at the logging boundary (regex-based); the LLM itself still sees real input, since it needs to answer. Prompt-injection defense is "minimal" as required.md asks — the system prompt frames retrieved content as data, not instructions — and a small adversarial test confirms this is *not* fully effective on the local model: 2 of 3 injection styles tested (persona hijacking, fake-authority privilege escalation) succeeded against `mistral-16k`, while a direct system-prompt-exfiltration attempt was resisted. Documented honestly as a known gap rather than glossed over.

**Future work.** Harden prompt-injection defense (stronger system-prompt wording and/or an output-side check) given the confirmed gap above; temperature sensitivity analysis (required, not yet run); a fix for the ~50% citation-hallucination rate on the local model; multi-turn-specific improvements once the current diagnosis (retrieval-side vs. generation-side) is complete.
