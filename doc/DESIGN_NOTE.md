# Design Note

This case study treats 488 converted MultiDoc2Dial documents as a surrogate internal knowledge base. The corpus spans English, Chinese, mixed-language content, Markdown, DOCX, TXT, text PDFs, and scanned PDFs. A frozen release contains 100 development and 100 holdout questions; the development set has 71 answer, 19 clarification, and 10 refusal tasks. It is an adapted evaluation set rather than an official MultiDoc2Dial benchmark.

The retrieval pipeline converts each format to Markdown, cleans presentation noise, creates section-aware chunks, embeds them with a pinned BGE-M3 revision, and stores verified vectors in Chroma. Experiments on the 488-document corpus rejected BM25 and dense/BM25 fusion as defaults. Dense retrieval supplied 20 candidates to a pinned BGE reranker; scoring 384-token windows instead of truncating long chunks improved Context Precision while keeping relevant parts of large sections visible. Returning five chunks gave the best measured cost/precision trade-off. A late audit found that an OCR paragraph had been interpreted as a heading and then dropped when its oversized parent was split. The versioned fix preserves heading-only leaves. On 71 development answer questions, complete evidence hits rose from 46 to 47 for windowed top-5, with no paired loss.

The service uses one shared runtime for the CLI, HTTP API, and evaluation. It supports isolated sessions, multi-turn history, health and reset endpoints, validated JSON output, exact citation-ID checks, a low-confidence refusal, bounded input, a 45-second provider timeout, and at most two attempts. DeepSeek Flash runs at temperature 0 with thinking disabled. Request logs contain run/config IDs, stage latency, retrieved IDs, usage, cache state, and error categories; PII is redacted at the logging boundary. User text still reaches the external model, a boundary the deployment owner must assess.

Evaluation separates generation from judging, pins every input and code hash, checkpoints each item, keeps failures in the denominator, and uses independent cost caps. Faithfulness is claim-level and Context Precision uses the pinned RAGAS 0.3.1 prompt through the same audited Flash transport. Correctness v1.3 is retained as an uncalibrated automated proxy. A broader v1.4 clarification rubric failed its diagnostic and was rejected. This negative result, two generation failures, OCR/alignment gaps, and the unmet accuracy target are reported rather than hidden. The next investment should be a small expert-labeled judge calibration set, followed by targeted clarification-policy work and OCR quality controls.
