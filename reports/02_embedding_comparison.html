Which embedding model actually reads across languages?

BGE-M3 and multilingual-e5-large, run on the winning chunk set from step 2, scored against the same gold-evidence retrieval harness — plus the BM25 baseline for reference. OpenAI's text-embedding-3-large is wired into the same pipeline but not run here (no API key configured this round).

199 chunks embedded 85 answerable questions 1024-dim, both models 18 cross-lingual test cases

Recommendation

BGE-M3

It wins on every overall metric — but the deciding margin isn't overall recall, it's cross-lingual retrieval. On the 18 test questions where the query language differs from every required document's language (e.g. a Chinese question whose answer lives in an English page), BGE-M3 finds the right chunk in the top 5 67% of the time. Multilingual-e5-large manages 6% — barely above BM25's 0%. For a corpus that's deliberately English/Chinese/mixed with dedicated cross-lingual test cases, that gap is the whole ballgame.

multilingual-e5-large is not a bad model — on same-language ("aligned") questions it's essentially tied with BGE-M3, and it embeds the corpus 1.7x faster. It just isn't multilingual in the sense this project needs.

01How this was measured

Same harness as the chunking comparison (src/chunking/evaluate.py) — only the retriever changes, from BM25 to cosine similarity over each model's embeddings, so the embedding model is the only variable. Each model encodes queries and passages the way its own documentation specifies: multilingual-e5 needs its "query: "/"passage: " prefix convention or it underperforms; BGE-M3's own model card says no prefix is needed. The query for each test question is its full conversation history plus the final question, exactly as a real multi-turn retrieval call would see it.
